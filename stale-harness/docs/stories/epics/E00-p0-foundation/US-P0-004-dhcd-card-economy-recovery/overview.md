# Overview

## Current Behavior

`REQ-P0-005` remains `provisional` and `B-REVERSE-001` remains active because
the exact DHCD card offer count, active selection algorithm, cost, and copy cap
have not been recovered. One packaged Android `1.304` `fp_` candidate now has
exact decoded weight rows, but both `fp_` and non-`fp` candidates are present
and the runtime-selected source is not proven. Native ISIL now recovers the
non-`fp` decoder path and embedded key literal, but that key produces invalid
UnityFS magic; the available Android capture likewise fails encrypted AssetBundle
loads and is not valid selection proof. Generated declarations name the
random-skill flow, while reconstructed method bodies contain invalid IL,
missing-method placeholders, and stack/type errors.

Exact named ISIL starts now uniquely map all 26 `LevelRandomSkillCtrl` methods
to BattleCore pointer slots `4182`-`4207`. Focused ARM64 slices prove propagation
of caller-provided random counts and a remaining-count loop. Generic registration
and an exact 1,540-byte pre-`RET` slice now recover cumulative-weight selection
 with predicate-controlled replacement as a high-confidence reconstruction. The
 threshold path is exactly `FP.op_Implicit(0)` followed by
 `TSRandom.Next(FP zero, FP cumulative-total)`; `NextFP` endpoint/distribution,
 active config/weight binding, caller values,
cost, and cap remain unresolved. iOS `1.351` also packages both logical names in
opaque DODAB1 envelopes; that is versioned candidate evidence, not active-source
or plaintext proof.

`US-P0-004` is the fourth Harness delivery story. It is linked to
`REQ-P0-005`; its numeric suffix does not identify `REQ-P0-004`.

## Target Behavior

The reverse lane has a reproducible, reviewer-auditable evidence packet and a
fail-closed serialized-candidate inspector. Candidate row values may be
published with their exact bundle/hash/version caveat. Runtime parity values
require the exact package/build key, proof of active source selection, and
native or successful runtime corroboration.
Server role binaries additionally prove that a 1,879-row center `900` candidate
is an exact subset of the byte-identical 2,023-row battle `999`/Android `fp_`
candidate. This candidate relationship does not select the Android winner.
Until then the story and `R-DHCD-001` remain `in_progress` and no parity
constants are introduced.
